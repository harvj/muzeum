# Muzeum numbered roadmap

Canonical roadmap, updated 2026-11-16. This file supersedes milestone ordering and authentication requirements in the dated repository assessment, January notes, P1.0 proposals and original P1.1 plan. Those documents remain historical evidence. Muzeum is the application; no legacy Muzeus database migration is planned.

1. **P1.0 — Foundation and data contract.** Baseline and design completed: [results](p1.0/baseline-results.md), [source/interpretation contract](p1.0/foundation-and-data-contract.md), [import acceptance plan](p1.0/import-requirements.md). Original security failures are historical, not current audit results. Preserve existing Muzeum IDs and source payloads.
2. **P1.1 — Production foundation.** Deliver in the substeps below. Production uses the existing Hetzner host, isolated PostgreSQL databases/roles, Caddy, systemd, Capistrano, dedicated Restic repository/subaccount and Healthchecks. CI never deploys.
   - **P1.1a — Deployment preparation:** completed locally at `96024b9`; infrastructure inventory, Rails-native shell, protected routes and manual exact-SHA deployment guards. Its password scaffold is superseded by P1.1d OIDC.
   - **P1.1b — Dependency modernization:** completed at `b3a0147`; Ruby 3.4.12, Rails 8.1.4.1 and security remediation. See [report](p1.1b/dependency-modernization.md).
   - **P1.1c — Backup preparation:** restricted Storage Box authentication/confinement, encrypted backup, disposable restoration and repository integrity verified. Healthchecks prepared and tested. Production capture, independent recovery escrow and scheduled activation are separate gates: [current readiness](p1.1c/backup-activation-readiness.md).
   - **P1.1d — First usable production deployment (deployed; initial backfill running):** existing `auth.harvj.com` identity through established Ruby OIDC code/S256 client; stable issuer/subject profile; no independent passwords, public registration, new Auth account or MFA enrollment. Associate a validated public Last.fm username, import historical observations server-side with atomic durable page checkpoints, idempotency, bounded retries and per-user serialization. Preserve raw responses independently of canonical identities. Show persisted counts, distinct observed names, time range and import status/errors in Rails/Hotwire. Use shared harvj typography, stationary naturalistic limestone/onyx assets and occasional localized illumination, static/reduced-motion fallback. Implement the shared session dropdown in Muzeum and document compatible CE/Auth changes without redeploying them. Exit requires tests, security/CI, desktop/mobile light/dark previews, recording, commit/push, isolated production restoration, rollback proof, operator recovery and real-browser OIDC verification. Deployment is authorized only after gates pass; backup schedules stay disabled until recovery is independently verified. [Implementation and gates](p1.1d/status.md).
3. **P1.2 — Production-scale ingestion hardening.** Extend the initial importer to shared LastfmAccount associations, explicit collision/metadata-change issues, detailed provenance/actors, 250k synthetic benchmark and fault matrix, independent throughput/RSS/digest evidence and production coverage validation. Preserve the P1.1d archive, raw pages and existing IDs. No MusicBrainz dependency. P1.1d delivers the usable bounded importer; it does not claim the full benchmark/account-sharing contract.
4. **P1.3 — Authenticated listening archive.** Rails-native keyset timeline, observation details/provenance, search/date filters, unresolved/collision visibility and scoped queries. Test two-user isolation, UTC/DST, stable pagination, Turbo behavior and query plans. Advanced browsing is outside P1.1d.
5. **P1.4 — Progressive resolution.** Independent asynchronous MusicBrainz resolution with immutable assessments, attributed versioned/scoped decisions, ambiguity review, edition context and history. Repair existing resolver/ingest defects before enabling them. Never mutate source observations or run resolution from the historical import path.
6. **Later — Derived reporting and incremental scheduling.** Rebuildable scoped DailyListen aggregates, durations/timezones/ranks/charts and scheduled incremental import after source and interpretation contracts stabilize. Recommendations, streaming, social features, Spotify and playlists remain deferred.

The primary security boundary is the local issuer/subject profile and its authenticated session. Last.fm association grants access to a public archive and does not prove source-account ownership. Identical same-second deliveries lack upstream durable event IDs; report this limitation rather than inventing certainty. Unresolved observed names are never canonical MusicBrainz artist/album/track entities.
