# P1.0 — Foundation and data contract

Status: proposal for review, 2026-11-15. Baseline execution completed; application/schema implementation has not begun. This document supersedes conflicting architectural proposals in the January context notes and the original assessment. See [baseline results](baseline-results.md), [import requirements](import-requirements.md), and the [updated roadmap](../repository-assessment-2026-11-15.md#5-numbered-implementation-roadmap).

## 1. Confirmed contract

Muzeum is definitive. Muzeus is a reference for browsing, navigation, presentation and reporting only. There is no legacy database migration, legacy mapping import, or competing archive writer in this plan. Preserve existing **muzeum** records during its schema transition.

The initial source archive is approximately 250,000 Last.fm scrobbles. Observation ingestion must work with MusicBrainz unavailable, no surfaces assigned, no canonical records, and no browser login. A trusted CLI/worker imports with the application's Last.fm API key. Browser import requests, if introduced, require Muzeum authorization. The source API does not authenticate a Muzeum user or prove who owns the source account.

Source observations and their original metadata are immutable and independently inspectable. Surface membership and identity interpretation are downstream. Canonical identity is incremental, evidence-based and revisable. Ambiguity remains unresolved. Every decision has an authenticated human or registered automated actor, evidence, timestamps and a reason; a revision retains its predecessor. New evidence may cause an assessment with no new decision. A decision can cover many compatible observations without copying decision history to each scrobble.

## 2. Current versus proposed model

Reviewed: all models and migrations, `db/schema.rb`, clients, importer/parser, resolver/runner, candidate extractor, release ingestor, seeds, specs, routes, CI and dated architecture notes at `3fa3e0a`. The executable baseline confirms both bootstrap paths agree, but does not validate the following missing contracts.

| Concern | Current implementation | Proposed disposition |
| --- | --- | --- |
| Muzeum User | `lastfm_username` is required/unique; no credentials or sessions; destroys scrobbles/imports on deletion | Retain user IDs; separate login identity from source account; deactivate users instead of cascading history deletion |
| Source account | Implicitly identical to User | Add LastfmAccount and user/account associations; one archive per source account, potentially several independent Muzeum viewers |
| Scrobble provenance | `user_id`, UTC time, parsed jsonb payload; no user FK | Add source account, first import/page, identity version/hash, raw-source availability; keep existing payload/time unchanged |
| Event deduplication | Unique `(user_id, played_at)`; conflicts silently skipped by insert_all | Account-scoped exact source fingerprint; retain/report differing same-second observations; do not infer event equivalence from timestamp alone |
| Bulk import | 200-row insert_all; two API requests per loop; three-page default; growing JSON notes; cursor uses maximum played_at | Retain bulk insert and pure client boundary; bounded page processing, durable range checkpoints, explicit backfill/replay, per-account serialization |
| Raw observation | Parser selects fields and strips text; payload may be JSON object or JSON string | Preserve current representation honestly; future pages stored verbatim and event locator retained; full parsed source object without normalization; no fabricated historical raw data |
| Surface | Global normalized artist/album/track strings; first observed MBIDs; current recording/release; mutable candidate/log arrays | Keep recurrence grouping; representative strings are display, never authoritative substitutes for individual payloads; remove global resolution authority |

| Canonical entities | MBID unique indexes, model presence checks; incorrect direct has_manys; track membership loses repetitions | Retain entities and IDs; fix joins/idempotency later; separate selected edition/track context from recording identity; no unverified canonical creation |
| Resolution | Surface.recording_id and bulk update of every attached scrobble; no actor/history | Add scoped immutable decisions and assessments; indexed current head; no global mutation of personal interpretations |
| Evidence | Candidate array/index and ingest_log; failed transaction loses logs | Immutable assessment snapshots (provider response, source evidence, human rationale, algorithm version); append failures/no-change assessments independently |
| Summaries | DailyListen table/model; no aggregation; user_timezones table only | Derived per-user interpretation, account filter and provenance coverage; rebuildable, never source truth |

Observed defects to carry to implementation: repeated resolution count increases from 1 to 2 for the same event; actual repeated release ingestion raises a unique violation; memoized spec masks that second call; current existing-release matching uses title; global surface bulk relinking crosses users; nullable MBIDs remain possible via bulk writes; scrobble-user and ingested-release FKs are absent; removed IngestEvent association remains. Details and reproduction are in the baseline report.

## 3. Users, accounts, actors and authorization

Keep the existing `users` table as the Muzeum principal; do not replace it with Last.fm accounts. Introduce local email/password authentication using Rails' built-in authentication patterns, bcrypt, and revocable server sessions, adapted to the existing User rather than blindly generating a new table. Initially provision users through an operator command/invitation; open registration is unnecessary. Add a minimum password policy, login throttling, generic login/reset responses, secure session cookies, CSRF checks and session revocation. Password recovery requires a configured local mail delivery path; until available, an explicit operator reset procedure is preferable to a broken recovery UI. [Rails authentication and session guidance](https://guides.rubyonrails.org/security.html#authentication).

`LastfmAccount` stores the provider username/normalized lookup key and source state, not a password, session key, OAuth token or API key. The application API key stays in environment/secrets. `UserLastfmAccount` means “associated archive,” not “verified owner.” Two Muzeum users may associate the same public account and have separate corrections. Verification remains unknown unless a separate, evidence-backed verification process is approved; no ownership inference from importing a public archive. Provider renames/case changes require explicit reconciliation; never guess account identity or merge accounts solely by similar names.

| Action | Smallest server-side policy |
| --- | --- |
| Read canonical catalogue | Public read-only, independent of login/provider availability |
| Read public-source history | Explicit source visibility policy; authenticated-only private views where required; no user-private notes in public output |
| Associate account | Authenticated User creates only their own association; normalized source account deduplicated; association grants no provider ownership |
| CLI/worker import | Registered service actor and operator-configured account allowlist; no browser session required |
| Browser request to import | Authenticated user, active association, explicit import permission and quotas; queued worker rechecks authorization; unverified association may import public data |
| Feedback/correction/manual resolution | Authenticated user, active association and resolution permission; writes only that user's scoped interpretation for that account |
| Shared canonical assertion | Registered approved resolver or separately granted canonical-curator capability; ordinary feedback is a proposal, not a shared canonical edit |
| Remove association | Revoke own view/import/resolution rights and invalidate sessions/jobs as needed; source archive/decision history retained; other users unaffected |

Do not trust request-supplied actor/user IDs, service names, scope owner or permissions. Derive actor from authenticated session or registered process configuration. Account ownership verification and application permission are separate fields. A verified owner would still not gain authority to rewrite another Muzeum user's private decisions. Service actors have explicit allowed operations/accounts; their identity is attribution, not a credential or permission by itself.

Authentication is required before browser resolution actions, not before CLI bulk import or public read-only browsing. Direct scoped authorization is sufficient initially; no general RBAC framework, Last.fm OAuth, shared admin URL token, or additional authentication service.

## 4. Concrete relational proposal

This is a proposed additive PostgreSQL design, not migrations. All new IDs are bigint; timestamps are UTC timestamptz where supported explicitly, with existing Rails timestamp conventions documented during transition. Unless marked optional, fields are NOT NULL. All FKs use RESTRICT/NO ACTION for historical source, actors, decisions and canonical references; no history cascades. Add indexed FKs when not covered by an index below. SQL checks guard enums, ranges and mutually exclusive targets; ordinary form validations alone are insufficient. Mutable operational tables have created_at/updated_at; immutable rows have recorded_at and no generic update interface.

### 4.1 Account and authentication extension

| Table | Proposed fields / relationships | Indexes and invariants |
| --- | --- | --- |
| `users` (retain) | Optional email_address/password_digest while existing accounts are unclaimed; `activated_at`, `disabled_at` optional; `canonical_curator` boolean default false | Unique normalized non-null email; credentials required for activation, never autogenerated from Last.fm usernames; no destructive dependents on source/history. `lastfm_username` transitional only |
| `sessions` (P1.3) | user_id FK, created_at, expires_at, optional revoked_at/IP/user-agent | user_id; expires_at; signed secure opaque session cookie; server revocation. No Last.fm credentials |
| `lastfm_accounts` | username, normalized_username, optional provider_user_id if verifiably supplied later; created_at; optional import_disabled_at | Unique normalized_username; unique non-null provider ID if adopted; username normalization is separate from musical-string normalization |
| `user_lastfm_accounts` | user_id FK, lastfm_account_id FK, associated_at, optional revoked_at; can_import/can_resolve booleans; optional ownership_verified_at, verification_method/evidence | Unique `(user_id,lastfm_account_id)`; reverse account/user index; defaults unverified; verification fields all absent or explicitly evidenced. Revocation removes permission, not archive data |

Keep user_timezones; add missing user FK after audit and later validate non-overlapping effective ranges. Keep DailyListen user linkage; future aggregates use the user's effective resolutions over associated accounts. They must not conflate “same source imported twice” with “two listens.”

### 4.2 Observation and import extension

| Table | Proposed fields / relationships | Indexes and invariants |
| --- | --- | --- |
| `scrobbles` (retain) | Add lastfm_account_id FK, first_import_run_id/page_id optional for existing rows, page_item_position optional, source_format (`legacy_parsed`/`lastfm_xml_v1`), identity_version, source_fingerprint, optional source_timestamp_seconds; preserve payload/time and add full unmodified parsed source for new observations if payload structure requires a separate source_payload column | Unique `(lastfm_account_id,identity_version,source_fingerprint)`; `(lastfm_account_id,played_at DESC,id DESC)` for browse/ranges/collisions. Do not make time alone unique. Keep old user_id temporarily as lineage, not ownership or event identity |
| `import_runs` (retain) | Add lastfm_account_id FK, requested_by_actor_id FK, mode, requested_from/to, fixed_upper_bound, checkpoint range/page, parser/identity versions, status, numeric counters (received/inserted/exact_repeats/conflicts/invalid/nowplaying/retries), started/completed/heartbeat_at, sanitized last_error | `(lastfm_account_id,created_at DESC)`; partial unique active run per account plus account advisory lock; completed status distinct from paused/page-budget exhaustion; checkpoint commits with page insertion |
| `import_pages` | import_run_id FK, sequence/attempt, sanitized request bounds/page/limit, fetched_at, status code/provider error, raw_body bytea (PostgreSQL compression), checksum, optional parsed metadata; processing state/counters/checkpoint stored separately or controlled mutable columns | Unique `(import_run_id,sequence,attempt)`; run/sequence index; immutable raw body/request/response facts; never persist api_key in request fields. Failed response bodies retained; retries have new attempts |
| `import_issues` | import_run_id/page_id FKs, item position optional, source account FK, played_at optional, kind, diagnostic/evidence JSON, recorded_at; optional related_scrobble_id FK | Unique deterministic issue key per page/item/kind (or run/key for cross-page conflicts); index account/time and run/kind. Original issue evidence append-only; later resolution is separate interpretation |

New observations retain first-source page + ordinal, exact original source strings/MBID claims, and parsed UTC timestamp. Raw page bytes permit independent source inspection even if parsing was wrong. Existing parsed payloads stay unchanged and marked `legacy_parsed`; do not reconstruct imaginary XML. Empty or invalid timestamps, API errors, undated now-playing and malformed items are preserved in pages/issues but are not fabricated timestamped scrobbles.

**Identity contract:** Last.fm's recent-tracks response does not provide a documented durable event ID. Propose versioned SHA-256 over a deterministic length-safe encoding of account, integer source timestamp and exact artist/album/track strings (distinguish absent from empty). Do not case-fold, strip remaster markers or use canonical MBIDs to identify an event. MBID enrichment/loved/image/URL/formatting changes are source evidence changes, not automatically a new listen: retain the new response in import_pages plus an issue when its metadata differs, keeping the first stored observation intact. Compare stored exact identity fields on hash conflict; quarantine a true hash collision instead of dropping it. A format/identity algorithm update needs an explicit migration/compatibility check; increasing the version must not duplicate the archive on replay.

Different identity tuples at the same second are retained as conflicting observations and flagged; they are not silently discarded, merged or automatically treated as independent proven listens. Read-only history shows the conflicting rows and pending status; summary totals distinguish accepted observations from pending collision candidates. Byte-identical multiple plays at the same second cannot be distinguished from duplicated delivery by this API. Preserve source page multiplicities and report that ambiguity; do not invent IDs from pagination position. No design can promise upstream identity certainty absent an upstream ID. Full replay guarantees preservation of received evidence, not recovery of unavailable upstream facts or historical deletions.

Use bulk insert with targeted conflict handling, not blind “ignore every constraint violation.” On each committed page, insert observations/issues, update bounded counters and checkpoint atomically. No surfaces, canonical writes, evidence resolution or DailyListen work in this transaction. Permissions gate the request and worker; they are not an external provider credential dependency.

**Immutability:** protect account/time/payload/fingerprint/first-source/provenance fields against UPDATE and DELETE with database triggers or separate DB grants plus triggers where the runtime role still needs updates. Include insert_all/update_all/delete_all tests: callbacks alone do not enforce the contract. Import pages and assessments/decisions are append-only for evidence fields. Exceptional operator retention/erasure policy must be explicit and audited separately; User.destroy is not such a policy.

### 4.3 Surfaces and scope selection

Retain RecordingSurface as a recurrence index based on conservative strings; its strings and MBIDs are representative, not replacements for scrobble payloads. Its current global recording/release fields become deprecated compatibility caches and are never used as authoritative personal interpretation after cutover.

Add downstream scrobble `surface_compatibility_key`, `surface_assignment_version` and `surface_assigned_at` alongside the nullable recording_surface_id. Set the four together once, after import, in bounded batches. Index `(recording_surface_id,surface_assignment_version,surface_compatibility_key,id)` and a partial index for unassigned scrobbles. Fix normalize(nil album) without weakening artist/track validation. Attachment can only go null→assigned; counts are derived from unique attachments. Normalization versions must not move historical members in place; a later regrouping requires its own additive assignment history design. P1 keeps immutable membership, using narrower scopes for corrections instead.

The compatibility key is a versioned digest of the normalized string tuple **and exact observed artist/track/album MBID claims with explicit missing values**. Different claims, including known versus missing, do not automatically share a reusable assertion. Unsupported identifiers remain claims, not canonical evidence. A surface alone is insufficient to authorize resolving all members.

### 4.4 Minimal resolution ledger (five domain tables)

No generalized event bus, aggregate snapshot framework or per-scrobble decision copies. Scope selects recipients; assessment stores evidence and reevaluation; decision stores versioned interpretation. Membership rows for a cohort are selectors, not duplicated decisions.

| Table | Fields / relationships | Constraints and lookup |
| --- | --- | --- |
| `resolution_actors` | kind (`user`/`process`), user_id optional FK, process_key/version optional, created_at, optional disabled_at | Exactly user XOR identified process; unique user_id where user; unique process_key/version where process. Preserve actor records on user deactivation. Register a distinct actor/version for changed automated logic |
| `resolution_scopes` | owner_user_id optional FK (null = shared assertion), lastfm_account_id optional FK, recording_surface_id FK; selection_kind (`compatible`/`cohort`/`observation`), compatibility_key/assignment_version for compatible, scrobble_id FK for observation; optional played_from/to restrictions; selector_digest, created_at; optional current_decision_id cache | Unique selector_digest **within owner scope**, using separate partial unique indexes for shared vs user or PostgreSQL NULLS NOT DISTINCT. Digest includes target/account/bounds/version/claim signature; confirm typed fields on conflict. User scope always has source account. Check exact fields required per selection kind; observation account/surface must agree |
| `resolution_scope_members` | scope_id FK, scrobble_id FK | Composite PK; reverse scrobble/scope index. Only for cohort; explicit immutable selected IDs, same surface and (where restricted) account. Freeze before first assessment; no later inserts/deletes. To change cohort, make a new scope with explicit precedence/replacement review, never edit recipients silently |
| `resolution_assessments` | scope_id FK, actor_id FK, prior_decision_id optional, assessed_at/recorded_at, outcome (`change`/`no_change`/`defer`/`error`/`feedback`), reason text; immutable evidence JSON array, evidence_digest; optional representative_scrobble_id/page_id FKs; optional algorithm/config/input digest; request/idempotency key | `(scope_id,recorded_at,id)`; unique `(scope_id,id)` for scoped FK; unique non-null request key per actor. Evidence entries have kind, provider/source identifier, fetched/submitted_at, content or immutable snapshot locator+hash, source page/scrobble references and rationale; never URLs alone. prior_decision belongs to same scope. Private user evidence stays private |
| `resolution_decisions` | scope_id FK, revision positive integer, previous_decision_id optional FK, assessment_id FK, state (`resolved`/`unresolved`/`inherit`), recording_id optional FK, release_id optional FK, decided_at/recorded_at, revision_reason | Unique `(scope_id,revision)` and `(scope_id,id)`; historical index `(scope_id,recorded_at DESC,revision DESC)`; unique assessment_id and unique non-null previous_decision_id to disallow duplicated outcomes/forks; previous and assessment must belong to same scope. resolved requires recording; unresolved/inherit require null target fields. `inherit` is allowed only for user scopes and explicitly removes that override; unresolved is an intentional blocking override |

Decision actor/evidence/decision source are obtained through its immutable assessment and actor, not redundantly copied. Every changing decision requires a `change` assessment, substantive reason and supported unique target. Failed or no-change assessments create no new decision. Evidence JSON is deliberately bounded domain data with a validated schema; large provider responses can use immutable snapshot pages rather than an ever-growing scope log. Separate normalized evidence tables are unnecessary until actual reuse/query needs justify them.

**Consistency enforcement:** all selection-kind, enum, timestamp-range, actor-kind and target nullability rules use CHECK constraints. Use composite FKs for `(scope_id,previous_decision_id)` and `(scope_id,assessment_id)` against matching unique keys; include `(id,current_decision_id)` from scopes to `(scope_id,id)` on decisions. Validate same-account/surface cohort/observation references and closed cohort membership using narrowly scoped triggers plus service tests (CHECK cannot read another row). Require revision 1 to have no predecessor; subsequent revisions must reference the locked current head and increment its revision exactly once. A decision's assessment must have outcome `change`, and its actor must have permission for that scope. Verify the frozen cohort's member digest before its first assessment. Canonical release/recording compatibility is validated atomically by the service against verified edition membership; unknown edition is null, never guessed. Actor identity, scope selectors, evidence and decisions cannot be edited to retroactively change meaning; only operational disable flags and the scope head projection can change.

Transaction sequence: lock scope → verify expected head/version and authorization → validate evidence/target → insert assessment and decision revision → advance scope head with compare-and-swap → commit. Human retries with the same idempotency key return the original result; stale forms/jobs receive conflict and must reassess. Scope head is the only mutable resolution projection and must point to the newest revision. Periodic consistency query verifies head against max revision; no global mass relinking of scrobbles. Imported raw source has no current recording field dependency.

### 4.5 Applicability, exceptions and reconstruction

Compatible selection requires matching surface, grouping version, exact compatibility key, optional source account and time bounds. Use it only when supporting evidence establishes a reusable musical identity for that signature. Manual evidence specific to selected listening events defaults to a frozen cohort, not “all present and future surface members.” Identical strings/MBIDs are not proof by themselves. Newly imported events matching a rule can inherit only a previously approved reusable assertion; conflicting claims stay out and trigger a fresh assessment. No-op reevaluation records evidence without changing the head or rewriting prior decisions.

Effective current interpretation for viewer User U: **U's explicit observation override → U's cohort → U's compatible scope → applicable shared assertion → unresolved.** A scope state `unresolved` blocks lower-priority fallback; `inherit` deliberately falls through. Distinct applicable scopes of equal priority with different targets yield an explicit conflict/unresolved result, not newest-wins. Identical targets may be combined as supporting assertions. Query code must not allow an older overriding cohort to disappear just because a new broader rule was added. Shared refinements never overwrite a private explicit assignment; shared changes appear through versioned read projections and must be visible as shared changes, not masquerade as the user's own correction.

Shared scopes may also have observation/cohort exceptions under curator authority. Shared decisions require canonical-curator or an approved resolver grant; a user's subjective note cannot directly create them. Shared evidence published from user feedback must exclude private data or obtain explicit publication authorization.

Examples:

- 5,000 compatible observations can read one shared scope head and one decision chain. Revising it creates one new decision, not 5,000 histories.
- The same normalized surface has studio and live MBID claims. Compatibility keys differ, so selecting studio cannot relink the live observations.
- U heard one mislabeled track in the same signature. An observation-scoped U decision overrides that event only. V's interpretation and the source row are unchanged.
- U corrects 200 particular listens using event-specific evidence. One U cohort and 200 selector rows share one decision chain. The correction does not automatically apply to the next matching scrobble.
- A fresh provider response confirms the current target. Append `no_change` assessment, preserving the current decision ID/revision.
- A correction is withdrawn. Append `inherit`; never delete the old correction. A clear-to-unresolved revision is different and continues to suppress shared fallback.

For reconstruction along Muzeum's **recorded decision timeline** at T, select the highest persisted revision per applicable scope with recorded_at ≤ T, scrobbles recorded by T and attachments recorded by T. Fixed cohorts and immutable compatible selectors reproduce recipients without snapshotting every event per revision. Use DB-assigned recorded_at and serialized revision order; timestamps alone do not resolve concurrent writes. Exact reconstruction of a scope uses its revision/decision ID. recorded_at is assigned during the transaction, not PostgreSQL's actual commit instant: do not claim forensic cross-transaction wall-clock snapshots while a transaction was in flight. A stronger commit chronology would need separately reviewed database support. Playback date is a separate axis, not the decision timestamp. Old evidence snapshots must be inspectable even if the live provider response changes.

This reconstructs identity interpretation, actor and evidence. Historical canonical *display labels* need either the cited metadata snapshots or a later metadata-version table; mutable Artist.name alone cannot reproduce a past label. Do not claim full historical catalogue reconstruction from resolution IDs alone. Historical user/account access grants may need a separate authorization audit if reconstructing access rights is later required; it is not necessary for reconstructing musical decisions.

**Efficient lookup:** account/time/id keyset page → attached surface/key → indexed matching scopes and cohort/observation selectors → scoped current head → decision/assessment. Restrict candidates to the page and viewer, never load all 250,000 events to filter in Ruby. Scope head yields O(1) chain access; historical index yields latest-before-T per relevant scope. Validate plans and bounds using the benchmark. A per-user per-scrobble current-resolution materialization is optional only after measurement; it would be a disposable projection, never another source of truth.

### 4.6 Canonical metadata

Retain Artist/Recording/Release IDs and unique MBID indexes. Fix through associations and restrict historical deletion. Validate non-null/valid provider IDs before tightening DB constraints. Reuse client/service boundaries and fixtures. Scope decisions identify canonical records; ordinary user feedback cannot mutate shared titles/MBIDs or join memberships as a side effect.

Proposed edition contract remains for review: Release identifies a selected MusicBrainz edition; group MBID supports navigation, not interchangeability. Extend release_recordings into track occurrences with medium_position, track_position, source_track_mbid/title/duration, allowing repeated recording IDs; unique edition/medium/track position replaces unique edition/recording. Keep flattened display position if useful. Do not treat membership in all releases as listening attribution. This is P1.3 work, not a prerequisite to source import.

## 5. Data-preserving transition within muzeum

1. Review proposal and capture a backup/restore rehearsal for any existing **muzeum** data before implementation touches it. Inventory counts, payload representation, orphaned users, duplicate/null canonical IDs and source time collisions. No muzeus database access or import.
2. Add LastfmAccount/association tables and nullable account FKs. For every existing User.lastfm_username, create/deduplicate a source account and associate the same User ID as **unverified**. Backfill scrobbles/import runs by that exact mapping in bounded, restartable batches. Validate all references/counts. Conflicting case-normalized usernames require review, not automatic user merging. Do not invent emails/passwords or claim that a Last.fm name authenticated a user.
3. Keep existing Users inactive/unclaimed until explicitly provisioned as local Muzeum principals. Trusted CLI import takes source account, not login state. Preserve old scrobble.user_id/import_run.user_id as transitional lineage; map requester actor to an identified migration process where historical initiating user is unknown. Retain original values; unknown past agency is not rewritten as a present-day human decision.
4. Add source identity/provenance columns and import page/issue storage. Backfill fingerprints from preserved parsed payloads with `legacy_parsed` provenance; audit exact duplicates versus timestamp conflicts before replacing the old unique index. Add account FKs/indexes concurrently where appropriate, validate constraints after backfill; then switch importer to account identity. Preexisting raw XML cannot be recovered from current selected fields. Do not remove old uniqueness while old code still relies on it; cut over writer/index contract together under paused imports.
5. Introduce optional attachment metadata and resolution tables. Preserve existing canonical pointers as **unverified historical baseline evidence**, attributed to a migration process with extraction timestamp and original IDs, not invented historical decision timestamps. Imported assertions are pending review unless sufficient existing evidence supports them. Keep original candidate/log JSON snapshots; there is no recoverable earlier decision history. Conflicting surface/event pointers are exceptions, not mass-reconciled automatically.
6. Switch interpretation readers/writers to the scoped ledger; prohibit old global relinking paths. Source-recording pointers are deprecated caches only until retired. Test two-user isolation and as-of reconstruction before allowing manual/automated revisions. Authenticate before browser write routes; CLI processes use explicit actor/grants.
7. Remove obsolete User.lastfm_username and scrobble user/recording cache fields only in a later cleanup after reconciliation and reader cutover. DailyListen rebuilding depends on the new scope rules, not those columns. Down migration must refuse to discard new multi-account/history data; rollback uses a pre-cutover backup or retained additive compatibility fields. Do not dual-write conflicting authorities indefinitely.

No migration, model, importer, authentication endpoint or production configuration in this proposal has been implemented in P1.0.

## 6. Recommended P1.1 sequence and review decisions

P1.1 should deliver the **observation foundation and measured bulk import**, not browser resolution.

1. Add meaningful failing tests for source immutability, account separation, timestamp collisions, boundary pagination and checkpoint atomicity. Preserve the baseline result; fix memoized retry-test structure when the resolution/ingest layer is addressed, without describing current green tests as retry proof.
2. Add account/association and source import schema in small reviewed additive migrations; test transition on existing muzeum-shaped fixtures and preserve IDs/checksums. Provision a registered importer actor; no human login requirement for trusted source imports. Permissions are checked in CLI/job services, not merely controllers.
3. Implement raw page capture, immutable source inserts, deterministic identity and conflict diagnostics. Stream pages, bulk insert in bounded transactions, expose numeric progress, checkpoints and resumable statuses. Use fixed upper bounds, boundary overlap and replay; no MusicBrainz, surface resolver or analytics in import.
4. Execute deterministic 250k local and mocked-network benchmarks, then a separately approved paced live-source validation. Publish measurements and corpus/manifest digests. Do not call the 250k requirement met by the present 49 tests or an empty-table microbenchmark.
5. Deliver read-only source inspection hooks and a runbook; P1.2 builds the browser. Preserve future ledger integration seams and provenance without prematurely building authentication or canonical resolution in P1.1.

Review items before P1.1 migrations: proposed fingerprint and collision policy (including indistinguishable same-second duplicates); raw response retention/storage budget; existing muzeum backup/transition inventory; minimal source visibility/import grants; performance gates. Review before P1.3: edition/track semantics, local authentication provisioning/reset policy, curator grants, compatible-rule versus frozen-cohort selection, scope precedence and historical-query guarantees. These are proposed implementation choices, distinct from the confirmed user decisions in section 1.
