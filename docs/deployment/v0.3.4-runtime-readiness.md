# v0.3.4 candidate runtime readiness

The existing hosted Brakeman run emitted duplicate `Gem::URI` constants from both RubyGems and Bundler’s vendored library, then exited 5 after reporting that Brakeman 8.1.0 was no longer current. Updating only the scanner to 8.1.1 exposed a distinct Ruby 3.4.12 security finding. The candidate pins Ruby 3.4.13 in `.ruby-version`, the Gemfile and the lockfile, and preserves `--ensure-latest` and existing CI exit gates. The duplicate startup warnings are diagnostic noise from overlapping vendored libraries. No warning suppression or workflow change is included. [Ruby advisory](https://www.ruby-lang.org/en/news/2026/11/18/multiple-vulnerabilities-in-regexp-and-string/)

The review base is deployed v0.3.3, `024ed4aecd98984c00323377389cde5a6a35d16d`. The combined diff includes Resolution Review evidence and scope, Wikimedia artist geography and qualified flags, shared navigation and canonical Auth login. It has no application schema changes or requests to modify production data. Production v0.3.3’s web and worker were active. Ruby 3.4.13 was absent from the checked Muzeum rbenv path and the Muzeum/Auth system runtime paths. The installed coordinator, runtime check, migrator, recovery tooling and service configuration still reference 3.4.12. The normal non-deploying Capistrano preflight verifies the live baseline and the candidate’s CI. Its result cannot validate a candidate interpreter it has not exercised.

Before production cutover, separately review and authorize staging the verified Ruby 3.4.13 build and locked bundle for Muzeum, then align its Capistrano, service, inspector, migration, and recovery runtime selection. Retain the Ruby 3.4.12 environment for the v0.3.3 baseline during compatibility and rollback verification. The interpreter selection must respect exact release pins and leave Auth and the other applications untouched. Repeat the guarded preflight against the reviewed runtime handoff before deploying.
