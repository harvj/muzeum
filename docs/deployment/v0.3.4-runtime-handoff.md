### Proposed privileged control review

Keep `641e09e` as the release-branch artifact and develop the deployment changes on the control side of the existing two-checkout workflow. A clean synchronized control checkout verifies its reviewed installed helpers, while the release checkout separately binds scope, ancestry, version and CI to the exact application SHA. Add explicit review and receipt fields for control SHA and the installed runtime manifest digest. Verify both identities on each phase of the locked operation. The current checks do not yet enforce that combined contract.

Stage a root-owned manifest that maps exact application SHAs to one of two fixed profiles. The old Auth prefix is available only for inspecting the installed v0.3.3 baseline. The forward SHA and the rollback SHA both map to `/opt/muzeum/ruby-3.4.13` and a dedicated bundle directory. The coordinator should reject unreviewed SHA/profile combinations, runtime-directory symlinks, non-root-owned or writable interpreter paths, and interpreter or reviewed helper checksum mismatches. Selection should come from the trusted deployment record and verified release, never an arbitrary environment variable or a writable release file. Before starting either Muzeum unit, the coordinator and unit launcher must agree on the profile for the published release. Isolated recovery should resolve the snapshot SHA and the target app SHA independently while keeping data-plane credentials separate.

Keep the default main path and current root helper behavior until the new controls pass tests. Separately review the specific rollback edge from the failed forward SHA to the compatibility SHA under the existing recovery lock. It is not a forward-ancestry exemption for other releases. Preserve backup and recovery references in both receipts. Verify tests for unapproved SHA, incompatible schema, mismatched manifest, concurrent lock contention and old-baseline inspection. No updated root-owned helper binaries or manifest have been approved or installed. The current installed coordinator handshake checksum is recorded above and identifies the old controls only.
