# P1.5.3c Canonical Auth login

Anonymous **Log In** and **Open your archive** lead to Muzeum’s `GET /login`. The public root stays usable without initiating login. An existing valid Muzeum session goes directly to `/archive`. A deliberate new visit starts the existing Auth authorization-code flow with S256, nonce, browser-bound state, confidential client authentication and the existing `openid offline_access` registration. Auth owns password, MFA, membership and token issuance. Muzeum verifies the signed token. Its existing native-assurance default accepts Auth’s approved behavior. An explicitly reviewed `OIDC_REQUIRED_ACR` can require an exact signed assurance value, such as `urn:harvj:assurance:mfa`. No production assurance setting changed. [Canonical Auth contract](https://github.com/harvj/auth/blob/main/docs/integrations/application-login.md), [Auth assurance contract](https://github.com/harvj/auth/blob/main/docs/application-assurance.md).

Protected top-level HTML navigations can carry a short-lived signed handoff to `/login`. Only recognized local archive, catalog and resolution reads are eligible. The server-side attempt digest binds the browser nonce, configured callback and validated local destination. A stale tab may fail explicitly. It cannot use a newer tab’s destination or invalidate its attempt. The callback consumes a matching browser-bound state atomically, rejects duplicate or ambiguous response parameters, and rotates the local session on success. An authentication attempt begun before cutover may require an explicit retry. Existing established sessions remain compatible. No schema change is required.

Prefetches, frames, background fetches and mutations cannot initiate login. Failed callbacks, provider outages, rate limits, logout and detected revocation stop at the public homepage with deliberate retry available. Muzeum rechecks owned grants at the existing 60-second boundary. Local logout uses the existing CSRF-protected DELETE, clears the application session and attempts to revoke the owned grant even if Auth is unavailable. `GET /session/new` and `POST /session` are retired. The registered `/oidc/callback` and `DELETE /session` remain.

## Auth dropdown and release order

Auth’s enabled, active-membership menu uses the exact registered client’s `application_entry_paths` value on the registered callback origin. The reviewed entry for this Muzeum candidate is `https://muzeum.fm/login`. Establish the consumer route before the Auth operator configures the Muzeum client’s entry as `/login` in the protected approvals file. Use the existing configuration mechanism. No simultaneous Auth deployment is necessary. Do not point the menu to the callback. Any existing approved `/archive` entry continues to work for normal browser navigation. Auth’s origin-root fallback lands on Muzeum’s public page. Repoint a configured `/login` entry to `/archive` before rolling back to a Muzeum revision without the canonical route.

Disposable browser coverage verifies the application dropdown destination with and without an existing Muzeum session, provider-owned fresh login and MFA, failure and retry, and public and private navigation in Light and Dark at desktop and mobile sizes. A live smoke test and live dropdown configuration verification follow separate deployment authorization. No production configuration or sessions were changed for this candidate.

The isolated Auth checkout passed 30 examples using disposable registrations and database state. The menu test used Muzeum’s exact callback and configured `/login` entry, including active-membership and unsafe-entry checks. Auth’s native OIDC tests covered MFA, grant invalidation and code replay.
