## Scope and bounds

An explicit artist import or refresh first completes MusicBrainz's own revision. A separate existing catalog-queue request then checks the unique MusicBrainz Wikidata URL against the artist item’s active P434. It retains selected original claims, ranks, date qualifiers, reference hashes, place hierarchy, entity revisions and request provenance in an append-only `ArtistGeography` catalog revision. This requires no migration and no new scheduler. Existing canonical artist identity, MusicBrainz fields, recordings, and release attribution retain their own rules. No bulk lookup is introduced.

For one unambiguous founding location, the policy prefers a verified constituent country found in its administrative ancestry. Otherwise it shows the founding locality, with a verified state or country as context when present. Historical and deprecated statements remain in provenance. Competing live founding, origin, country, or state evidence suppresses the derived origin. Missing or unreconciled links leave the MusicBrainz country as a readable fallback.

Wikidata Action API requests use an identified User-Agent, maxlag, four traversal rounds and a twelve-place bound, and at most five entity calls. Commons file metadata is batched in one request. Each provider shares a one-second minimum request spacing across workers, and the existing lease, 32-uncached-call and five-attempt ceiling still apply. New enrichment is capped at four MiB per response and uses a seven-day projection cache with a separate 200-row quota. The latest durable evidence stays visible after expiry with a refresh notice. A new artist refresh rechecks the evidence as needed. The artist detail and list each add one indexed catalog revision query and make zero provider API calls during rendering. [Wikimedia API policy](https://www.mediawiki.org/wiki/Wikimedia_APIs/Access_policy), [API etiquette](https://www.mediawiki.org/wiki/API:Etiquette).

The same place component renders artist origins, artist/release countries, and Resolution Review country metadata. Exact P41 assets are used for verified place flags. Commons metadata verifies the file, MIME, size and license. The browser caches the SVG/PNG from Wikimedia’s image CDN and sends no referrer. A missing or unlicensed file leaves the place name visible. National ISO flags apply only in the country-code fallback. The original file and distinct artist/place item links preserve attribution and evidence.

The proposed release scope combines P1.5.3a and P1.5.3b. The runtime security gate identified in P1.5.3a remains separate. No deployment, release publication, or production artist enrichment was performed.

The two captured acceptance cases each used five Wikimedia API calls. Their combined local replay took 1.77 ms. Four local browser response-start samples were 9, 8, 9 and 9 ms. Both measurements use disposable data and exclude provider and CDN network time. The full browser-inclusive suite passed 274 examples.
