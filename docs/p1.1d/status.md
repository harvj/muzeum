# P1.1d implementation and rollout record

Active milestone; see the [canonical roadmap](../roadmap.md). Production deployment is gated, not claimed complete by this implementation record.

Implemented: `openid_connect` Ruby client with exact production issuer, native confidential code/S256 flow, one-use server-side browser-bound state/nonce/verifier, signature/JWKS/RS256/issuer/audience/azp/nonce/expiry validation, stable `(issuer,subject)` local profile and encrypted durable grant storage. Existing Auth account/password/MFA are reused. No email-based linking, public registration or independent password flow. Local sessions last at most seven days/12 idle hours; native refresh-grant introspection is checked every 60 seconds, fails closed during outages and binds subject/client. Local logout works during provider outage. Historical source-only users remain unlinked until explicit operator reconciliation. Provider tokens are not used as Last.fm credentials.

Last.fm: public `user.getinfo` validation, current-profile-only association, no provider password. The existing Muzeus application API key was recovered privately and successfully validated; no key values are in this report/Git. Association ownership remains unverified. One username per local profile and one profile per username is an intentional P1.1d restriction; sharing/renames need P1.2 reconciliation.

Import: one 200-observation page per Solid Queue job, one-second pacing, a fixed inclusive upper time bound, durable atomic page/cursor/counter transactions, PostgreSQL row serialization, unique exact-name/time fingerprints, bounded five-attempt network/rate-limit retries and explicit resume/restart. Raw XML/checksum/page lineage is retained independently of optional recording/surface links. Database triggers prevent source fields/raw pages from bulk update/delete; `db/structure.sql` is the canonical schema bootstrap because schema.rb cannot preserve triggers. Existing parsed-only rows are not relabeled as raw source. Different same-second observations are retained and exact same-second repeats deduplicated; upstream certainty/collision issue modeling remains limited. Same-total upstream history edits cannot be detected reliably by this API; differing totals fail safely and can be restarted. No MusicBrainz calls, surface attachment, DailyListen aggregation or resolution work occurs.

Dashboard: actual scoped persisted observation totals, distinct exact observed names (album/track include artist), UTC earliest/latest timestamps and durable progress/error/update state. Unknown albums are omitted from album counts. Refresh explicitly requests current progress; no invented stats or canonical-identity claims. [Environment assets/previews/recordings](environment.md); [dropdown compatibility and admin-link limitation](shared-session-dropdown.md).
